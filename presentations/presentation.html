Context & Motivation
Problem Statement & Research Questions
1. Single-Agent Limits
• Cascading Errors: When an initial premise fails, standard chain-of-thought propagates falsehoods.
• Confirmation Bias: Single-prompt self-correction rarely overturns wrong hypotheses without external grounding.
2. TalkHier Paradigm
• Hierarchical Roles: Separates solving into Generation → Specialized Evaluation → Revision.
• Domain Verification Tools: Integrates SymPy truth-table generators & counterexample verifiers.
• Cloud Assumption: Original paper relied on proprietary GPT-4o; local feasibility unstudied.
3. BTP Objectives
• Open Model Viability: Can an 8.2B local model sustain multi-agent hierarchical reasoning?
• Homophily Bias: Do homogeneous agents share identical blind spots?
• Order Sensitivity: Does evaluator presentation order affect revision outcomes?
Research Question: Evaluating hierarchical multi-agent reasoning under local compute constraints

Week 2 Experiment B
Evaluator Agreement & Homophily Bias
100% Unanimous Consensus Flaw
14 / 14 Scores: 10/10
• Across all logged evaluation events, evaluators unanimously gave 10/10.
• In Problem 4 and Problem 6, incorrect hypotheses were confirmed with 10/10 scores.
• Scientific Nuance: Proves that homogeneous multi-agent teams share identical inductive blind spots; multi-agent consensus ≠ correctness.
Failure Case Study: Problem 4
Question: Translate PL formula (~B • E) ⊃ D into natural English.
Generator Output: Choice 0 (Incorrect: "both... not").
Ground Truth: Choice 1 (Correct: "both not").
Formal Logic Evaluator: Score: 10/10 ("Translation is accurate... matches choice 0").
Revisor Outcome: Maintained choice 0 due to 10/10 score confirmation.
Core Insight: Homogeneous agents reinforce each other's hallucinations instead of catching them

Proof: Evaluator registration order directly affects tool invocation and revision accuracy
Implementation Details
Engineering Challenges & Bottlenecks
1. Token Parsing
Issue: Qwen3:8B produces <think>...</think> tokens that broke JSON parsing.
Fix: Built regex post-processing filter in react_agent.py and llm.py.
2. Duplicate Tool Calls
Issue: Agents called truthtable_generator twice with identical inputs in ~50% of problems.
Impact: Wasted 2–3 minutes of CPU compute per problem.
3. Turn Latency
Issue: 8–14 sequential LLM calls per problem resulted in ~6 min/problem on M4 CPU.
Impact: Full 126 benchmark would require ~13 hours. Justifies focused 10-problem pilot.
Software integration bugs successfully isolated from genuine architectural failure modes
Roadmap & Next Steps
Conclusions & Phase 3 Research Plan
What We Proved in Weeks 1 & 2
✓ Feasibility: Ported TalkHier to local Qwen3:8B on M4 with $0 API costs.
✓ Competitive Baseline: 80.0% accuracy on Formal Logic pilot.
✓ Revision Value: +20.0% accuracy boost (60% → 80%).
⚠️ Homophily Flaw: 14/14 unanimous 10/10 scores confirm shared blind spots.
⚠️ Order Sensitivity: Reversing evaluator order dropped accuracy from 66.7% to 33.3%.
Proposed Phase 3 Research Improvements
1. Heterogeneous Evaluators: Introduce diverse specialist models or distinct system personas to eliminate groupthink.
2. Adaptive Confidence Routing: Skip evaluators when generator confidence is high, cutting CPU latency by ~40%.
3. Deterministic Tool Caching: Prevent duplicate truth table calls.
4. Order-Independent Pooling: Pool evaluator outputs in parallel to avoid registration bias.
